# Documentation site

The site is a static Rust program built with [Stucco](https://github.com/mcaveniathor/stucco), pinned to version 0.3.0. It uses Stucco's page renderer, components, theme bundle, and content-hashed assets. It needs no server at runtime.

The header's dark mode switch uses Stucco's `data-theme` attribute and `stucco-theme` storage key. It follows the system preference until a visitor chooses a mode, restores that choice before first paint, and shares it between both sites when hosted on the same origin. With JavaScript disabled, the switch stays hidden and the page follows the system preference. Custom site colors use `light-dark()` alongside Stucco's theme.

From the repository root:

```sh
cargo run --locked -p symposiast-site -- dist --base /symposiast/
python3 site/check_links.py dist --base /symposiast/
```

`--base` controls links and asset paths. Use `/` for a site hosted at the domain root. `dist/` is ignored by Git. Edit the Rust page shell in `site/src/`, prose in `site/content/`, and styles in `site/assets/`. The `site/downloads/` tree contains the validated, standalone Cargo projects copied into the site's `examples/` directory.

The [automation guide](content/automation.md) documents the reusable Symposiast action and release workflow examples.

The [maintainer guide](content/maintainers.md) is the canonical pilot and publishing guide. Both sites link to it. Keep the consumer trial instructions and issue-form links aligned with the registry's installation guide.

The site's navigation, homepage, and guides link to the separate [Symposiast Registry](https://mcaveniathor.github.io/symposiast-registry/). Its catalog, contribution instructions, and website source live in [the registry repository](https://github.com/mcaveniathor/symposiast-registry); edit those there rather than duplicating the catalog in this site.

For a local preview at the root path:

```sh
cargo run --locked -p symposiast-site -- dist --base /
python3 -m http.server 8000 --directory dist
```

## GitHub Pages

The Documentation workflow builds and checks the site for pull requests and branch pushes. It uploads a Pages artifact. Only `main` deploys; unmerged changes do not replace the public site.

In the repository's **Settings → Pages**, select **GitHub Actions** as the build source. Merge the documentation changes into `main` to trigger the first deployment. The resulting project site is `https://mcaveniathor.github.io/symposiast/`. The workflow can also be run manually once it exists on the default branch.

The workflow requires Pages to be enabled for the repository and the `github-pages` environment to permit deployments from `main`. No custom domain or third-party hosting credentials are required.

The Stucco downloads and guide section are generated from `plugins/stucco/bundle`. Run `python3 scripts/update_stucco_examples.py` after verifying an updated bundle; CI checks them with `--check`.

The clap, axum, and Bevy bundles are generated by Symposiast through its Codex adapter. Their findings, recipe code, coverage reports, manifests, and lockfiles feed the site directly. After generating and verifying updated bundles under `plugins/<crate>/bundle`, run `python3 scripts/update_examples.py` and `python3 scripts/update_examples.py --check`. CI checks these files for drift and compiles every downloadable project. Use `symposiast render` to validate a bundle, including recipe fingerprints, before updating the site.

Run `python3 scripts/check_axum_examples.py` to exercise all generated axum programs against localhost requests; port 3000 must be free. Bevy’s graphical consumers need Linux development libraries (on Ubuntu: `libasound2-dev libudev-dev libwayland-dev libxkbcommon-dev`) to compile, plus a suitable display and graphics environment to run. CI compiles those consumers and runs only the finite `hello` and `message` recipes.
